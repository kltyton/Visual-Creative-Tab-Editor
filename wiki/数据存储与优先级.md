# 数据存储与优先级

所有创造标签数据都属于世界数据包。服务端维护两个保留目录，并把普通数据包放在二者之间。

```text
最高优先级  visual_creative_tab_editor_player_overrides
            普通数据包（按玩家选择的包顺序）
最低优先级  visual_creative_tab_editor_generated_default
```

从旧项目名升级时，首次启动会把
`one_enough_creative_tab_generated_default` 和
`one_enough_creative_tab_player_overrides` 自动迁移为当前目录名。若目录移动失败，读取器仍会回退到旧目录并写入明确日志；旧的
`one_enough_creative_tab:custom/*` 自定义标签 ID 也继续受支持。

如果新旧目录同时存在，当前名称的目录保持权威，旧目录不会被删除，并会输出冲突警告，避免静默覆盖较新的编辑结果。

## 默认数据包

目录：

```text
<world>/datapacks/visual_creative_tab_editor_generated_default/
```

行为：

- 服务端每次启动都重新捕获当前原版和已注册 Mod 的最终标签内容。
- 只在文件发生变化或旧默认包不可用时触发额外重载。
- 数据包是必选、固定位置，并始终位于普通数据包下面。
- 新增或移除 Mod 后，默认层会按新的原生标签集合更新。

该目录由 Mod 管理，不要手工编辑；修改会在后续启动时被重建。

## 普通数据包

普通数据包用于可维护、可分发的服务器规则：

- 可以覆盖已有原版或 Mod 标签的单个字段。
- 可以新增纯 JSON `category` 标签。
- 多个包之间按真实选中顺序从低到高合并。
- 第三方包中的非法 JSON 或非法目录会拒绝本次资源重载，而不是静默吞掉。

手工定制应放在独立普通数据包中，不要直接修改两个保留目录。

## 玩家覆盖数据包

目录：

```text
<world>/datapacks/visual_creative_tab_editor_player_overrides/
```

行为：

- 可视化编辑器保存到这里。
- 数据包是必选、固定位置，并始终位于所有普通数据包上面。
- 已有标签只保存相对“默认层 + 普通数据包”的最小字段差异。
- 编辑器新增的自定义标签保存完整定义。
- 保存时会清理不再需要的差异 JSON。

因为保存的是差异，后来安装 Mod 新增的标签仍会从较低层出现。该覆盖是世界级设置，会同步给所有玩家，不是保存于某个客户端的个人配置。

## 服务端解析流程

```mermaid
flowchart LR
    A["原版和已注册 Mod 标签"] --> B["最低层 generated_default"]
    B --> C["普通数据包逐字段覆盖"]
    C --> D["最高层 player_overrides"]
    D --> E["服务端验证后的目录"]
    E --> F["同步给客户端并渲染"]
```

服务端同时保存：

- `base`：默认包与全部普通数据包的合并结果。
- `resolved`：在 `base` 上再应用玩家覆盖后的最终结果。

编辑器使用二者计算最小差异，而不是把整个当前目录无条件复制到最高层。

## 保存安全与并发

- 保存前重新检查游戏管理员命令权限。
- 草稿携带打开时的修订号，过期草稿会被拒绝。
- 全服同一时刻只提交一个完整编辑事务。
- 写入前备份 Mod 管理的玩家覆盖文件和当前目录状态。
- 写入或重载失败时恢复这些文件和目录状态，并向提交者重新同步。

这保证本 Mod 管理的覆盖保存可以回滚，但不等同于对所有第三方资源重载监听器提供全局 ACID 事务。

## 陈旧 Mod 数据

两个保留目录中的陈旧或损坏条目会记录警告并跳过，避免已经移除的 Mod 物品阻止世界启动。普通第三方数据包保持严格校验。
