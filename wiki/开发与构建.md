# 开发与构建

## 环境

| 项目 | 值 |
| --- | --- |
| JDK | Java `17` |
| Gradle Wrapper | 仓库自带 |
| Minecraft | `1.20.1` |
| Fabric Loader | `0.16.9` |
| Fabric API | `0.92.1+1.20.1` |
| Forge | `47.2.30` |

## 模块

- `common`：数据模型、JSON codec、服务器管理器、网络协议、运行时目录和公共编辑器。
- `fabric`：Fabric 入口、网络频道绑定、Access Widener 与 Fabric 分页适配。
- `forge`：Forge 入口、`SimpleChannel` 网络绑定、SRG Access Transformer 与 Forge 分页适配。
- `buildSrc`：共享多加载器 Gradle 约定插件。
- `wiki`：可直接同步到 GitHub Wiki 独立仓库的 Markdown 源文件。

## 常用命令

Windows PowerShell：

```powershell
.\gradlew.bat :forge:runData
.\gradlew.bat build
.\gradlew.bat :fabric:runClient
.\gradlew.bat :forge:runClient
```

最终 JAR：

```text
fabric/build/libs/visual_creative_tab_editor-fabric-1.20.1-2.0.1.jar
forge/build/libs/visual_creative_tab_editor-forge-1.20.1-2.0.1.jar
```

## 验证要求

只看到主菜单不代表创造标签功能已经验证。涉及运行时 UI 或分页的修改至少应覆盖：

1. `build` 成功。
2. Fabric 与 Forge 能完成资源、音频和纹理加载。
3. 实际进入创造模式世界。
4. 首次按 `E` 打开创造物品栏。
5. 至少执行一次编辑器相关操作。
6. 涉及资源目录时执行 `/reload` 后再次打开创造栏。
7. 检查 `latest.log`、新崩溃报告和 `[EditorTrace]`。

涉及分页时还应测试第 `11` 个普通标签、跨页拖动、左右边缘自动翻页、搜索标签和生存物品栏标签。

## 访问性变更

新增私有成员访问需求时按以下顺序选择：

1. 公共 API。
2. Fabric Access Widener / Forge SRG Access Transformer。
3. 只有行为注入才使用 Mixin。
4. 反射只作为最后手段，并且必须有失败处理和明确日志。

不要为纯字段或方法访问新增 Mixin Accessor/Invoker。

Fabric 使用 `visual_creative_tab_editor.accesswidener`，映射命名空间为
`named`。Forge 运行时使用
`forge/src/main/resources/META-INF/accesstransformer.cfg` 中的 SRG 成员名；
不要把 Mojmap 名称直接复制进 Forge 运行时 AT。

## 网络实现

公共 payload 只定义频道 ID 与 `FriendlyByteBuf` 编解码。Fabric 使用
Fabric Networking API 的频道注册，Forge 使用 `SimpleChannel`；接收端必须
校验方向并把处理调度到游戏线程。不要在 1.20.1 分支引入高版本的
payload/codec API。

## 数据和协议限制

修改 schema、目录限制或网络负载时，必须同步更新：

- `CreativeTabJsonCodec`
- `CreativeTabValidation`
- `PayloadChunks`
- 客户端与服务端 payload 注册
- [数据包格式](https://github.com/kltyton/Visual-Creative-Tab-Editor/wiki/数据包格式)
- [架构设计](https://github.com/kltyton/Visual-Creative-Tab-Editor/wiki/架构设计)

## Wiki 发布

GitHub Wiki 是独立 Git 仓库。首个页面创建后，将 `wiki/` 中的文件同步到：

```text
https://github.com/kltyton/Visual-Creative-Tab-Editor.wiki.git
```

`Home.md` 是入口，`_Sidebar.md` 和 `_Footer.md` 会由 GitHub 自动渲染为导航和页脚。只有推送到 Wiki 默认分支的提交会对读者生效。
