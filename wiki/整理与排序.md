# 整理与排序

“一键整理”作用于当前分类标签。搜索标签也支持整理，但保存的是全局搜索结果的首选顺序。

## 排序方式

| 界面名称 | 行为 |
| --- | --- |
| 按类型 | 按创造菜单语义类别及该类别中的原生物品顺序排列；顺序依次参考建筑方块、彩色方块、自然方块、功能方块、红石、工具、战斗、食物、原材料和刷怪蛋。Mod 自定义分类按当前标签顺序追加参与分组。 |
| 按 ID 名称 | 先比较完整 ID 中冒号后的路径，再用完整 ID 消除并列。 |
| 按物品名称 | 使用 Minecraft 当前选择语言对应的本地化比较规则；中文环境按中文显示名，英文环境按英文显示名。完全同名时按完整 ID。 |
| 按完整 ID | 按 `namespace:path` 排序。 |
| 按 Mod ID | 仅搜索标签提供；先按冒号前的命名空间排序，再按完整 ID。 |

## 按类型的含义

“按类型”不使用 Java 实现类名称。每件物品会取得其首次出现的语义创造分类和该分类内原生位置，例如武器跟随战斗分类、工具跟随工具分类、建筑方块跟随建筑分类。无法归入任何分类的物品最后按完整 ID 排列。

## 搜索标签的特殊行为

搜索标签的一键整理和手动拖动都写入 `items`。这里的 `items` 不是过滤白名单，而是首选顺序：

1. 已保存顺序中、当前仍真实存在的物品优先出现。
2. 新安装 Mod 后新增的物品不会消失。
3. 所有未出现在首选顺序中的搜索结果会自动追加。

因此，对搜索标签执行整理不会破坏以后新增 Mod 的搜索内容。

过滤搜索时也可以手动拖动。编辑器按完整 ItemStack 身份把可见结果映射回搜索工作顺序，同时保留本次筛选未显示的既有首选项。

搜索首选顺序同时受单标签 `items` 最多 `16384` 项和整个目录最多 `65536` 个物品项的限制。搜索聚合或目录总量达到上限时，仅剩余容量允许的前缀参与拖动或整理；越界操作会被拒绝并记录诊断日志。

## 保存

选择排序方式后只修改当前草稿。确认结果后点击“保存”；点击“取消”会恢复服务器上的原顺序。
