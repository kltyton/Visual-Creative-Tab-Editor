# 故障排查

## 长按没有进入编辑模式

依次检查：

1. 当前是否打开创造物品栏，而不是普通生存物品栏。
2. 玩家是否拥有服务端“游戏管理员命令”权限。
3. 是否按住鼠标左键约 `500 ms`。
4. 长按期间鼠标是否移动超过约 `12 px`。
5. 长按空白时，位置是否真的是边框或标签栏空位，而不是槽位、滚动条、翻页按钮或其他控件。

权限变化大约每 `20` 个服务端 tick 复核一次。刚刚授予权限后可以稍等一秒再重试。

## 修改或新增物品没有反应

物品选择器只接受玩家物品栏中的非空槽位：

- 不要点击创造物品列表中的槽位。
- 不要点击空槽位。
- 新增、替换和选择标签图标都使用相同规则。

只有 `category` 标签可以直接编辑物品。搜索、快捷栏和生存物品栏使用特殊原版行为。

## 物品放回创造物品栏后没有消失

先确认已经退出编辑模式。正常模式下，原版创造物品栏点击逻辑会继续执行；编辑模式会拦截槽位输入以完成选择和拖动。

## 保存后提示目录已经变化

这是修订冲突：另一笔保存或任何成功的 `/reload` 在草稿打开后推进了
服务端修订号；即使重载后的目录内容相同，旧草稿也不会自动合并。

1. 关闭冲突草稿。
2. 重新进入编辑器取得最新目录。
3. 再次执行修改并保存。

## 保存被拒绝或一直保留草稿

可能原因：

- 保存时权限已被移除。
- 另一项保存正在提交。
- 标签或物品数量超出限制。
- 标签类型、原版固定身份或 ItemStack 数据无效。
- 上传或资源重载失败。

客户端会显示系统消息，服务端日志会记录具体异常。普通失败会尽量保留草稿，不会假装保存成功。

## `/reload` 失败

第三方数据包采用严格校验。重点检查：

- 路径是否为 `data/<namespace>/creative_tabs/<path>.json`。
- 是否出现未知字段或显式 `null`。
- `format` 是否为 `1`。
- ItemStack 是否存在、非空且 `count` 为 `1`。
- 物品 ID、数据组件和背景 Identifier 格式是否有效。
- 原版 `hotbar/search/inventory` 是否保持固定类型。
- 是否至少保留一个可见分类标签。
- 是否超过标签、物品、文档或网络限制。

不要直接修补 `visual_creative_tab_editor_generated_default` 或 `visual_creative_tab_editor_player_overrides`；手工规则应放在独立普通数据包。

## Fabric 或 NeoForge 客户端崩溃

报告问题时请附上：

- Minecraft、加载器、本 Mod 和 Fabric API 的准确版本。
- `logs/latest.log`。
- `crash-reports/` 中最新报告。
- 能复现问题的数据包 JSON。
- 问题发生前的操作，例如“首次打开创造栏”“拖动到第二页”或“保存后 `/reload`”。

开发运行目录中的典型位置：

```text
fabric/runs/client/logs/latest.log
fabric/runs/client/crash-reports/
neoforge/runs/client/logs/latest.log
neoforge/runs/client/crash-reports/
```

编辑器详细状态使用日志前缀：

```text
[EditorTrace]
```

提交问题前不要只截取最后一行异常；完整调用栈和相邻 `EditorTrace` 才能确定实际状态转换。
