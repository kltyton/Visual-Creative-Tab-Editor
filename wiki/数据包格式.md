# 数据包格式

Visual Creative Tab Editor 从服务器数据资源中读取创造标签定义。

## 文件路径与标签 ID

```text
data/<namespace>/creative_tabs/<path>.json
```

资源路径同时决定标签 ID：

```text
data/example/creative_tabs/building/favorites.json
-> example:building/favorites
```

数据包本身还需要一个适用于 Minecraft 1.21.1 的标准 `pack.mcmeta`；服务器数据包格式为 `48`。

## JSON v1 完整示例

```json
{
  "format": 1,
  "title": { "text": "Favorites" },
  "icon": { "id": "minecraft:diamond", "count": 1 },
  "items": [
    { "id": "minecraft:diamond", "count": 1 },
    { "id": "minecraft:enchanted_golden_apple", "count": 1 }
  ],
  "search_items": [
    { "id": "minecraft:diamond", "count": 1 },
    { "id": "minecraft:enchanted_golden_apple", "count": 1 }
  ],
  "hidden": false,
  "order": 20,
  "type": "category",
  "can_scroll": true,
  "show_title": true,
  "aligned_right": false,
  "background": "minecraft:textures/gui/container/creative_inventory/tab_items.png"
}
```

## 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | 整数 | 缺省为 `1`，当前只支持 `1`。 |
| `title` | Component JSON | 标签标题，可使用 `text` 或 `translate` 等 Minecraft 文本组件形式。 |
| `icon` | ItemStack JSON | 标签图标；必须非空且 `count` 必须为 `1`。 |
| `items` | ItemStack 数组 | 分类标签中实际显示的有序物品列表。搜索标签中表示首选搜索顺序。 |
| `search_items` | ItemStack 数组 | 分类标签对全局搜索贡献的独立列表；不要求与 `items` 相同。 |
| `hidden` | 布尔值 | `true` 时隐藏标签并停止其 `search_items` 对全局搜索的贡献，但保留身份。 |
| `order` | 整数 | 升序排列；相同时按完整标签 ID。范围为 `-1000000` 到 `1000000`。 |
| `type` | 字符串 | `category`、`search`、`hotbar` 或 `inventory`。 |
| `can_scroll` | 布尔值 | 是否使用可滚动物品区域。 |
| `show_title` | 布尔值 | 是否显示标签标题。 |
| `aligned_right` | 布尔值 | 是否使用原版右侧特殊标签布局语义。 |
| `background` | Identifier 字符串 | 创造物品栏背景纹理 ID。解析时只验证 ID 格式，不验证纹理文件一定存在。 |

`title` 使用 Minecraft Component codec；`icon`、`items` 和 `search_items` 使用 Minecraft 1.21.1 的注册表感知 ItemStack codec，因此可以保留数据组件。

## 多数据包合并规则

同一个标签 ID 可以由多个数据包共同定义。资源按真实选中包顺序从低到高逐字段合并：

- 字段缺省：继承较低优先级数据包中的值。
- 字段出现：整体替换该字段。
- `items` 或 `search_items` 写成 `[]`：清空该列表。
- 数组不会自动追加。
- 显式 `null` 非法，不能用来删除或重置字段。
- 未知字段会使第三方数据包重载失败。

例如，只修改原版建筑方块标签图标：

```text
data/minecraft/creative_tabs/building_blocks.json
```

```json
{
  "format": 1,
  "icon": { "id": "minecraft:diamond_block", "count": 1 }
}
```

## 新建数据包标签

新 ID 缺省时会使用安全默认值，但建议至少显式提供 `title`、`icon`、`items` 和 `search_items`。只有 `category` 类型可以作为新的运行时标签加入。

纯 JSON 新标签不会注册进 Minecraft 的冻结注册表。它会出现在本 Mod 管理的创造界面中，但只枚举内建注册表的第三方代码可能看不到它。

## 特殊标签约束

- `minecraft:hotbar` 必须保持 `hotbar`。
- `minecraft:search` 必须保持 `search`。
- `minecraft:inventory` 必须保持 `inventory`。
- `hotbar` 和 `inventory` 不能配置 `items` 或 `search_items`。
- 搜索标签的 `items` 只是首选顺序，不会过滤后来新增的搜索结果。

## 限制

| 项目 | 上限 |
| --- | --- |
| 标签总数 | `512` |
| 单个标签 `items` | `4096` |
| 单个标签 `search_items` | `4096` |
| 整个目录两种列表合计 | `65536` |
| 标题展开文本长度 | `32768` 个 Java 字符 |
| 单个 codec JSON 值 | `131072` 个序列化字符 |
| 单个标签 JSON 文档 | `2097152` 个 Java 字符 |

完整目录必须至少保留一个未隐藏的 `category` 标签。
